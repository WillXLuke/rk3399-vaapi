# RK3399 VA-API hardware video (NanoPC-T4, Armbian, Linux 7.3.1)

VA-API hardware **decode and H.264 hardware encode** for the Rockchip RK3399
(FriendlyElec NanoPC-T4), on a mainline 7.3.1 kernel.

| Feature | Status |
|---|---|
| H.264 decode (VA-API, rkvdec) | working, **bit-exact** vs. software |
| HEVC Main decode | working, **bit-exact** |
| VP9 P0 / MPEG-2 / VP8 decode | working (VP9 close but not bit-exact) |
| H.264 encode (VA-API EncSlice, VEPU2) | working, CQP + frame-level CBR/VBR, Constrained Baseline/Main/High |
| JPEG hardware encode | via the stock hantro driver (not VA-API) |

The interesting part: mainline Linux has **no H.264 encoder driver for RK3399**
(the hantro driver exposes JPEG only). This repo contains the port of Bootlin's
VEPU2 H.264 encoder stack to 7.3.1, the missing stateless-encode UAPI/control
types, and a VA-API encode frontend.

## Layout

```
docs/                     write-ups: results, design, limitations, handoff
userspace/                libva backend (decode + encode), MIT
kernel/hantro-encoder/    ported VEPU2 H.264 encoder driver + encode UAPI, GPL-2.0
kernel/rkvdec-module/     out-of-tree rkvdec wrapper (decode node), GPL-2.0
scripts/                  build / install / load / restore helpers
tests/                    decode + encode smoke tests
```

## How it fits together

* Decode: `/dev/videoN` (rkvdec, stateless request API) + `userspace/`
  (`v4l2_request` VA driver). Installed as
  `/usr/lib/<arch>/dri/v4l2_request_drv_video.so` with `panfrost`/`rockchip`
  aliases, so no `LIBVA_DRIVER_NAME` is needed.
* Encode: the `hantro-VPU` driver is extended with the VEPU2 H.264 encoder
  (`S264` capture format + `V4L2_CID_STATELESS_H264_ENCODE_*`), which also
  needs a rebuilt `videodev.ko` for the new control types. The same VA driver
  exposes `VAEntrypointEncSlice`.

## Build and install (on the target board)

Userspace driver:

```sh
./scripts/build-userspace.sh
sudo ./scripts/install-userspace.sh
```

Kernel modules (needs a configured kernel source tree matching the running
kernel, e.g. extracted 7.3.1 sources):

```sh
./scripts/build-kernel-modules.sh /path/to/linux-7.3.1
sudo ./scripts/install-kernel-modules.sh /path/to/linux-7.3.1
sudo ./scripts/load-media-stack.sh
```

## Usage

```sh
vainfo --display drm --device /dev/dri/renderD128

# decode
ffmpeg -hwaccel vaapi -hwaccel_device /dev/dri/renderD128 \
       -hwaccel_output_format vaapi -i input.mp4 -f null -

# encode (H.264, CQP)
ffmpeg -vaapi_device /dev/dri/renderD128 -f lavfi \
       -i testsrc2=size=1920x1080:rate=30 -t 5 \
       -vf format=nv12,hwupload -c:v h264_vaapi -qp 26 -bf 0 out.h264
```

## Limitations

* Encode rate control is a frame-level QP controller (no hardware RC); CQP,
  CBR and VBR are accepted. One reference, no B frames, single slice.
* SPS/PPS are generated by the VA backend; packed-header mode is not used.
* The rebuilt `videodev.ko` / `hantro-vpu.ko` must be rebuilt after every
  kernel upgrade. Rollback instructions are in `docs/HANDOFF.md`.
* `kernel/` is GPL-2.0; everything else is MIT (`LICENSE`, see `NOTICE.md`).
